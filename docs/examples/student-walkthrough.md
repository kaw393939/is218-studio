# Walk through it as a student

This is an authored rehearsal of the instructions, not a study of typical students. It does not claim real attendance, group participation, submission, grades or learning gains. Use it to ask whether each handoff is understandable.

## One route through the term

| Moment | What the student does | What carries forward |
| --- | --- | --- |
| **Current RPS-001** | Opens the actual Canvas task, predicts a round, completes the supplied workflow and checks it. | The student's own RPS repository and `SPEC.md`; the original rubric stays intact. |
| **Launch** | Researches three roles, compares two portfolio directions and two game concepts, and chooses a group customer from the kit. | Three evolving records: portfolio career/design, creative game and shared simulated-customer workflow. |
| **Next class** | Brings a draft and one task; a peer tries it. Records a specific issue and responds. | Improved plan and observable checks, not another report. |
| **Review 1 → 2** | Uses the plan to build the first useful path, then tests an independent expected result. | Current source, checks, contributions and a focused Studio receipt. |
| **Review 2 → 3** | Integrates required pieces; a real peer tries the complete task. | One useful problem to improve, a revision and known limits. |
| **Finish week** | Makes the change, retests, repairs links/setup and rehearses. No new topic. | Same record/URLs; proposed final-ready target Dec 6. |
| **Demo** | Starts from the portfolio, shows the account/game/dashboard journey and group contribution, and explains evidence and limits. | A credible project story for later professional conversations. |

The later dates are **Planned** until Canvas posts them. The actual RPS-001 deadline is already posted. [Use the section card](/course/schedule) to avoid mixing the two.

## Confusions the site addresses

| Likely wrong turn | Clearer rule |
| --- | --- |
| “Do I need a separate new app for Studios and the creative project?” | The creative app may use any suitable stack and a simple game core. Add required accounts, saved results/dashboard and account maintenance; preserve the completed RPS001 baseline. |
| “Do two alternatives mean twice the entire build?” | Share core code/content. Compare one meaningful decision and explain the choice. |
| “Is this new schedule already in Canvas?” | Posted means an existing assignment; Planned means preparation target. No invented submission links. |
| “Are the example grades real?” | They assess the actual supplied packet; imagined peer/check claims receive no execution credit. Current RPS keeps its separate rubric. |
| “Does the HTML preview prove the backend/auth work?” | It proves a narrow browser interaction. RPS001 requires its exact Python checks. The final creative game needs actual account, private saved-score, dashboard and maintenance checks. These static previews are only slices. |
| “Can an AI customer approve my peer review?” | A simulated customer can clarify a scenario. Real classmates supply actual peer feedback and teamwork. |
| “Do I start something new in the final work week?” | No. Finish integration, missed reviews, meaningful fixes/retests and rehearsal. |
| “Does IS218 add another portfolio assignment?” | Yes: the updated plan requires a portfolio, beginning with career research and a short design process. You may improve a site you already own. |
