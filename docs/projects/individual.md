# Your individual creative application

Show that you can choose a useful experience, build a small version, check it and explain your work. **By default, extend the RPS application you already own.** Give it a creative direction and use the same repository, `SPEC.md` and tests for Studios and project reviews.

Already have another approved idea? Keep it. Agree a bounded scope and how to complete the required RPS skills without unexpectedly adding another stack or large application.

## A finishable scope

- One clear audience and main task.
- A working core you can explain, with a usable interface.
- Three to five user stories and meaningful success/failure checks.
- Two manageable approaches to a useful decision; choose one.
- Real peer feedback, at least one meaningful change and a retest.
- Reproducible setup, source, AI/help credit and honest limits.

A creative RPS could help a newcomer learn *why* a round was won. Compare an explanation beside the choices with an explanation on a result card. Keep the same rules; check whether a peer can explain the losing round. The supplied starter and AI help are credits, not work you independently invented.

## Carry it across the reviews

| Review | Small next result |
| --- | --- |
| 1 · Understand and plan | Choose the reader, compare two directions, write stories and checks. |
| 2 · First slice | Make one real round work and show the evidence for it. |
| 3 · Integrated build | Combine the assigned pieces; label unfinished work and choose a useful feedback issue. |
| 4 · Improve | Make the change, retest, hand off the selected version and explain the result. |

The [current RPS-001 task](/projects/studios#rps-001-posted) still has its original limited scope. Accounts/dashboard are prospective later Studios, not retroactive requirements. A static teaching preview does not establish those capabilities or server testing.
