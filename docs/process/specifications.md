# Plan something you want to build

A **specification**, or spec, explains what your application should do and how you will check it. Keep updating the same `SPEC.md` or [project record](/templates/project-record).

## Start big, choose a useful slice

For the creative project, use any language or framework. RPS is one starting point; another small game or useful workflow can work too. Use [the creative challenge](/projects/creative-challenge) to explore ideas with AI.

Write three short statements:

| Statement | What it means | RPS example |
| --- | --- | --- |
| **Dream** | The larger experience you would love to create. | A game where rival characters learn how I play. |
| **Promise** | The small experience you will finish and check this term. | Play a short match against two clearly different opponent strategies. |
| **Experiment** | An uncertain idea you will investigate. | Can AI help create a predictable opponent whose behavior I can test? |

An experiment may disappoint. Keep the promise small enough to finish even if that happens.

## Turn the promise into a plan

1. Name the audience and main task. Separate evidence from assumptions.
2. Compare two approaches. Choose one and explain its tradeoff.
3. Write three to five user stories: “As a [user], I want [action], so [benefit].” Give each an observable expected result and a relevant failure case.
4. Sketch the parts and how they connect. Separate the core rules from inputs and presentation where useful. Choose one small [pattern experiment](/process/architecture): compare two approaches, try the pattern in code, then decide whether to keep, refactor or remove it. Functions can express a pattern; classes and inheritance are optional.
5. Ask a classmate to explain what would count as working. Resolve unclear wording before building.

For groups, name an owner and a different reviewer for each useful slice. Everyone contributes design, development and checking.

## Keep learning in the same record

At each review, show the new behavior, a test, a design decision and what you learned from AI. Link the issue, actual code change and checks. Revise the plan when evidence changes it. Learning from a failed experiment is valuable; the promised experience still needs to work for completion credit.
