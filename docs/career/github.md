# Make your GitHub useful to a new reader

**Portfolio component.** Use this guide in your IS218 portfolio. Keep actual profiles, project claims and materials consistent. Follow the published Canvas portfolio reviews for dates, points and submissions. [Portfolio brief](/projects/portfolio) · [Your section's review links](/course/schedule).

Your portfolio shows the result; GitHub shows the source and how you worked. Link your **own profile**, individual repository and shared group repository. Do not duplicate the group's code just to claim a separate project.

## Short checklist

- [ ] My profile has a clear bio and a working portfolio link, if I have one.
- [ ] The relevant repositories are easy to find, with useful names and descriptions.
- [ ] Each README explains the purpose, setup, current scope and limits.
- [ ] The spec links actual checks, issues/PRs, contributions and AI/starter credit.
- [ ] A classmate can follow the setup; private data and secrets stay out of public code.

For RPS-001, keep the actual issue, final PR/CI links and full checks in `SPEC.md`; merge the completed work to `main` and submit your own repository URL. A reference/template URL is not your submission. [Exact current instructions](/projects/studios#rps-001-posted).

## Two short README examples

These are fictional teaching descriptions. Use only claims your own work supports.

**Individual — RPS application:** “A course project for practicing and explaining RPS rounds. The README identifies the completed Studio, setup, nine-outcome tests, integration/browser checks, and known limits. Starter and AI help are credited.”

**Shared — service inquiry:** “A team course project for requesting a room setup. My slice was form validation and error wording; my partner owned status/history. The public preview is synthetic and does not reserve a room.”

## Use it effectively

Keep setup commands accurate for the chosen revision. Link the existing spec instead of copying its whole history. Show a useful decision and test, not a long technology list or commit count. Pin strong work when helpful; a separate profile README is optional.

Ask a peer to find your contribution and run one project from its README. Fix the first missing step and try again. Include these links in the one portfolio you are building or improving for IS218.
