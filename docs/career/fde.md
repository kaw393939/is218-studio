# What is a forward deployed engineer?

An **FDE** works closely with a customer or business team to build useful software. They learn how people work, find a problem worth solving, build a solution, and help people use it.

For example, a service company receives incomplete requests. An FDE might talk with staff, improve the request flow, connect it to existing data, and check whether it saves rework.

## What IS218 helps you practice

Turn a rule into code, test every outcome, connect a web interface to server behavior, and explain the result.

| Professional habit | Your practice here |
| --- | --- |
| Learn what the user needs | Scope your individual application and your group’s business task. |
| Turn a need into behavior | Write a small spec with inputs, outputs, errors, and checks. |
| Build and debug | Choose an appropriate architecture; test its rules, interactions and failure behavior. Authentication needs tests when the task uses it. |
| Work with people | Use issues, branches, pull requests, and partner checks. |
| Deliver and explain | Demonstrate the workflow, show checks, and name remaining limits. |

This is a foundation. FDE roles often expect more programming, databases, cloud systems, customer work, or AI engineering. Read [job examples and pay](/career/jobs-and-pay) and [local internship leads](/career/internships) as targets to learn toward.

Try: “I’m an NJIT student building [workflow] for [audience]. My part was [contribution], and I checked it by [test]. I’m learning [next skill] and looking for [internship / part-time work / small client project]. What problems does your team work on?”

Browse [Meetup technology events](https://www.meetup.com/find/us--ny--new-york/technology/) around Newark, Jersey City, NYC, or online, and [NJIT career opportunities](https://www.njit.edu/careerservices/find-opportunities). Check the event’s format, age rules, and cost. No paid event is required. Listen first; ask before following up.
